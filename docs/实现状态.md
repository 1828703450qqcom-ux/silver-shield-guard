# 实现状态与功能边界

本页依据仓库源码与资源清单记录项目现状，用于区分**可展示的原型页面**、**本地逻辑**和**需要外部服务的规划能力**。它不是产品性能认证。

| 模块 | 当前代码 | 尚需完成或验证 |
|---|---|---|
| 适老化界面 | Jetpack Compose 页面、导航、字号/显示设置 | 多尺寸设备和无障碍实测 |
| 防骗训练 | 预置脚本、会话页面、训练记录与积分界面 | 用户研究、内容审核与效果评估；积分不对应现金 |
| 交易风险 | Room 实体、规则引擎、监测服务及演示交易；账户说明页不采集真实卡号或验证码 | 银行/支付方授权接口、合规数据接入、真实流水验证 |
| 来电风险 | 本地号码库、白名单、提示相关代码 | 系统角色/权限、实际设备上的识别与拦截效果验证 |
| 语音交互 | Android 语音能力及相关管理类 | 方言覆盖率和离线识别性能测试；没有“128 种”实测依据 |
| AI 模型 | ONNX Runtime 调用封装与规则回退 | 仓库没有 `.onnx` 权重、训练集与评测报告 |
| 举报材料 | 表单、案件页面与 PDF 工具 | 与公安或官方平台的真实提交接口及回执 |
| 家庭守护 | 页面和本地数据结构 | 跨设备同步、账户授权与服务端实现 |

早期文档中的模型准确率、方言数量、银行/微信/支付宝直连、现金红包等属于目标或示意，不是当前交付承诺。不要将本原型用于实际资金风控决策。

## 建议的下一步

1. 为规则引擎、数据库和关键页面补充可重复的测试，并建立稳定的演示数据集。
2. 在真实 Android 设备上验证通知、来电权限和后台行为，记录系统版本与设备型号。
3. 如需 ONNX 能力，提供可再分发的模型、输入预处理、标签映射、评测集与许可证，再进行端到端测试。
4. 如需金融或报案接入，先取得正规接口、授权与隐私合规方案，再开发服务端与审计日志。
